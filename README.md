# Панель модератора Discord (GitHub Pages)

Статический сайт: вход через Discord и выбор сервера. Работает без сервера и базы данных, поэтому подходит для GitHub Pages. Показываются только серверы, где у тебя есть права модератора (владелец, администратор, управление сервером, бан/кик, управление сообщениями, таймаут).

## Запуск на GitHub Pages

1. В репозитории: **Settings → Pages → Build and deployment → Source: Deploy from a branch**, ветка `main`, папка `/ (root)`. Через минуту сайт появится по адресу `https://ИМЯ.github.io/РЕПОЗИТОРИЙ/`.
2. Создай приложение на https://discord.com/developers/applications
3. В разделе **OAuth2 → Redirects** добавь адрес страницы возврата, точно такой:
   `https://ИМЯ.github.io/РЕПОЗИТОРИЙ/dashboard.html`
4. Открой `config.js`, впиши `CLIENT_ID` (Application ID из General Information) и закоммить.
5. Ссылка на политику конфиденциальности для бота: `https://ИМЯ.github.io/РЕПОЗИТОРИЙ/privacy.html`. Вставь её в General Information → Privacy Policy URL. Ссылка на условия пользования: `https://ИМЯ.github.io/РЕПОЗИТОРИЙ/terms.html` (поле Terms of Service URL там же). Контакт в обоих документах: Discord `nurs_bust`.

Client Secret этому сайту **не нужен и вставлять его нельзя**: всё, что лежит в репозитории, публично.

## Interactions Endpoint URL (слэш-команды бота)

Страница `interactions.html` показывает белую бесконечность из точек, которые раздвигаются от курсора или касания. Она самодостаточна и открывается и на GitHub Pages: `https://ИМЯ.github.io/РЕПОЗИТОРИЙ/interactions.html`.

**Но сам Interactions Endpoint URL не может работать на GitHub Pages.** Discord отправляет на него POST-запросы и требует проверку подписи и ответ, а Pages отдаёт только статические файлы. Поэтому в папке `endpoint/` лежит обработчик, который нужно запустить на любом сервере с HTTPS (код один и тот же):

- **Обычный Node.js-сервер** (VPS, Render, Railway, Replit и т.п., зависимостей нет, нужен Node 20+):
  ```bash
  node endpoint/node.mjs
  ```
  Адрес для Discord: `https://ТВОЙ-ДОМЕН/interactions`. При открытии этого адреса в браузере показывается страница с бесконечностью.
- **Cloudflare Workers** (бесплатный тариф, без своего сервера): из папки `endpoint/` выполни `npx wrangler deploy`, отдельно ключ задавать не нужно. В `wrangler.toml` можно задать `PAGE_URL` (адрес страницы на GitHub Pages), и браузер будет перенаправляться на неё.

Публичный ключ бота (Public Key) уже записан в `endpoint/config.mjs` и `config.js`: он не секретный. Если понадобится другой, поменяй его в обоих файлах (тест проверяет, что они совпадают) или задай переменную окружения `DISCORD_PUBLIC_KEY`, она имеет приоритет. Затем вставь адрес в поле **Interactions Endpoint URL** и сохрани: Discord сразу отправит проверочные запросы (PING и запрос с неверной подписью), и адрес сохранится только если оба прошли.

Что умеет обработчик: проверяет подпись Ed25519 (неверная подпись получает 401), отвечает на PING, обрабатывает слэш-команды (`/ping` и `/about` в качестве примера, остальные получают ответ «пока не реализована») и подтверждает нажатия кнопок. Свои команды добавляются в объект `commands` в `endpoint/handler.mjs`. Сами команды нужно зарегистрировать в Discord отдельно (через Developer Portal или API).

## Локальный запуск

```bash
python3 -m http.server 8000     # или: npx serve
```

Открой http://localhost:8000 и добавь `http://localhost:8000/dashboard.html` в Redirects Discord.

## Как это работает и ограничения

Используется implicit grant (`response_type=token`): Discord возвращает токен в адресе после `#`, страница `dashboard.html` забирает его, сразу стирает из адресной строки и истории и хранит в `sessionStorage` (только эта вкладка). Профиль и серверы запрашиваются из браузера напрямую у Discord.

- Токен живёт, пока открыта вкладка и не истёк его срок (его задаёт Discord). Обновления токена нет, после истечения нужно войти снова.
- Discord сам называет этот способ годным для прототипов. Токен выдан только с правами `identify` и `guilds`, то есть позволяет читать профиль и список серверов, больше ничего.
- Сайт только показывает данные и запоминает выбор сервера в браузере (`localStorage`). Любые действия модерации (баны, кики и т.д.) должен выполнять бот или отдельный сервер с настоящей проверкой прав: страница в браузере ничему не может доверять.
- Если позже понадобятся серверные функции (хранение настроек, действия от имени бота), потребуется бэкенд (например, Vercel или другой хостинг).

## Файлы

- `index.html` — главная с входом, `dashboard.html` — выбор сервера, `privacy.html` — политика, `terms.html` — условия пользования, `404.html`
- `app.js` — вход через Discord, `config.js` — настройки (Client ID)
- `style.css`, `drops.js` — оформление и капли
- `interactions.html` — страница с бесконечностью из точек; `endpoint/` — обработчик Interactions Endpoint (Node и Cloudflare Workers)
- `test/` — автотесты (`npm test`, нужен Node 20+, зависимости не требуются)
